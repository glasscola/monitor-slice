# 독립 출력 엔진 실험 기록

이 문서는 전용 출력 API를 시험한 과거 기록입니다. v1.4.1은 해당 전용 출력 경로를 사용하지 않고 기존 물리 바탕화면을 복제하는 별도 방식으로 배포됩니다. 아래의 미구현·배포 보류는 전용 출력 엔진에 대한 설명입니다.

이 변경은 개발 중이며 v1.3.0 공개 릴리스와 다릅니다. 물리 출력 공간 없이 네 논리 모니터를 한 패널에 표시하는 엔진은 완성되지 않았습니다.

## 실행 검증

`MonitorSlice.exe --direct-output-probe`는 물리 출력별 Windows 지원 플래그를 조회하고 DisplayManager.TryAcquireTargetsAndReadCurrentState로 실제 제어권 획득을 시도합니다. 성공한 경우 즉시 반환하며 모드를 적용하지 않습니다. 진단 전후 CCD 구성을 비교합니다. 보고서는 로컬 evidence/direct-output-probe.json에만 저장합니다.

2026-11-13 Windows 11 Pro 25H2, NVIDIA RTX 5060 Ti의 두 물리 출력에서 지원 플래그가 false이고 실제 권한 획득 결과는 0xD0000022였습니다. 전후 디스플레이 구성은 동일했습니다. 이 결과로 완전 분할 구현 성공을 주장할 수 없습니다.

## 현재 중계 모드의 창 접근 문제 수정

- 분할 세션 동안 250ms마다 출력용 공간에 생기는 일반 창을 검사합니다.
- 마지막 활성 분할 영역으로 창을 이동하고, 소유 대화상자는 부모 창의 영역으로 이동합니다.
- 화면에 보이는 다른 모니터의 창과 Shell 창은 이동 대상에서 제외합니다.
- 이동 실패를 확인할 수 있는 수동 복구 버튼을 제공합니다.
- 복원 전에 감시 타이머를 종료합니다.

`MonitorSlice.exe --window-safety-test`는 실제 화면 구성을 바꾸지 않고 자체 시험 창만 대상으로 새 창, 반복 위치 재설정, 소유 대화상자, 보이는 창 위치 보존을 검사합니다. 네 시나리오를 통과했고 세 번의 창 구조를 확인했습니다. 전체 분할 세션 통합 시험이나 관리자 권한 앱 호환성을 검증한 결과는 아닙니다.

## 다음 통과 조건

현재 OS와 출력에서 일반 바탕화면을 제거하면서 직접 영상을 표시하고, 프로세스 종료 시 자동 복구하는 경로를 먼저 확보해야 합니다. 이 경로가 확보되지 않은 상태에서 중계 모드를 독립 분할 모드로 표시하거나 새 릴리스를 게시하지 않습니다.
